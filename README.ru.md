# morin-filter

**Дешёвый корпусный приор для нейросетевых языковых моделей.** Смешивает
распределение следующего токена модели с n-граммными частотами из
локального корпуса. Микстура улучшает и перплексию, и точность top-1,
концентрируя вероятностную массу на гораздо меньшем числе кандидатов.

> 🇬🇧 **[English version](README.md)**

Название — в честь интуиции о *поверхности Морина*, с которой началось
исследование: большинство локально правдоподобных переходов в графе
токенов — «фантомы», они никогда не встречаются в данном контексте.
Таблица корпуса знает, какие переходы реальны, а вероятностная микстура
(никогда не жёсткая маска) использует это знание, не ломая хвост редких
токенов.

## Результаты (честный сплит 4:1, 300 запросов, DeepSeek-Coder-V2-Lite 16B MoE на CPU)

| Домен | PPL модель | PPL +morin | top-1 модель | top-1 +morin |
|---|---|---|---|---|
| JS/TS код | 14.7 | **9.0** (1.64×) | 50.3% | **53.0%** |
| Python код | 7.9 | **4.0** (1.98×) | 55.7% | **60.7%** |

## Установка

```bash
pip install numpy
git clone https://github.com/koshechkintimur-a11y/morin-filter.git
```

Требуется Python 3.8+. Для примера с llama.cpp: `pip install llama-cpp-python`.

## Использование

```python
from morin_filter import build_ngram_prior, CorpusPrior, MixtureScorer

# 1. Строим приор по ВАШЕМУ корпусу (токенизированному):
prior = CorpusPrior(build_ngram_prior(train_token_ids, order=2))

# 2. На каждом шаге: нормализованные log-вероятности модели (V,) и контекст:
scorer = MixtureScorer(prior, beta=0.3)
mix_logp = scorer.mixture_logp(model_logp, context_ids)

# 3. Сэмплируем / берём argmax / top-k по mix_logp вместо model_logp.
```

Или полный пример оценки:

```bash
python examples/llama_cpp_example.py \
  --model path/to/model.gguf \
  --corpus path/to/your/codebase.txt \
  --beta 0.3
```

## Что это и чем НЕ является

**Это не заявка на новизну.** Механизм — Jelinek–Mercer smoothing
(1980) в применении к нейросети, и упрощённый вариант kNN-LM
(Khandelwal et al., ICLR 2020) без эмбеддингового индекса.
Recency-родственник — Cache LM (Grave et al., ICLR 2017).
Карта предшественников: `docs/LITERATURE.md`.

**Что это:** намеренно дешёвый инженерный артефакт — корпусный приор,
который подключается к любой модели llama.cpp / transformers за минуты,
на CPU, с памятью в килобайты-мегабайты.

## История исследования

### Fracode Phase 0–1: эпоха сжатия

Проект начинался как **Fracode** — попытка построить фрактальный кодек
сжатия. Phase 0 дал бенчмаркнутый контейнерный кодек — и честное
поражение: `zstd` + словарь победил его на реальных данных. Phase 1 —
семантические кодовые книги, терминальная адресация, русский чат-корпус:
длинная серия отрицательных результатов, каждый из которых перед
записью убивался adversarial-проверкой. Эта фаза научила проекту
главной привычке: **если результат выглядит слишком хорошим — он
слишком хорош. Проверять, пока не сломается.**

### Fracode Phase 2: гонка геометрий

Вопрос стал: может ли геометрия адресного пространства (кривые Леви,
Гильберт, тессеракт, лента Мёбиуса, реле Пуанкаре) удешевить
маршрутизацию? Эксперименты A–Q измерили каждую предложенную геометрию
на реальных данных. Все проиграли простому евклидову k-means-роутеру;
идея маршрутизации сошлась к известному паттерну (MoE). Единственная
выжившая интуиция — *поверхность Морина как модель путей токенов* —
привела к открытию, что ~90% локальных циклов токенов — **фантомы**
(локально правдоподобны, глобально невозможны), и их отсечение помогает
и скорости, и точности. Из этого вырос корпусный приор этого пакета.

### Где мы оказались (честная бухгалтерия)

Победивший механизм оказался известным: Jelinek–Mercer smoothing
(1980), Cache LM (2017), kNN-LM (2020). После проверки литературы
выжил инженерный угол: **тот же выигрыш, что у kNN-LM, за долю
памяти** — простая n-граммная таблица вместо эмбеддингового индекса
миллиардного масштаба.

Полный путь — 22 эксперимента, пойманные фальсификации (лучшая: утечка
данных, завышавшая recall на 5 п.п.), проигравшие геометрии и один
выживший эффект — в `docs/FULL_JOURNEY.md`. Это журнал отсева гипотез,
и мы считаем его самой честной частью репозитория.
